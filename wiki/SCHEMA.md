# Wiki Schema

Conventions for the OSDM system design wiki. Read this first.

## Wiki location
- Wiki root: `wiki/`
- Raw sources: `raw/` (sibling of `wiki/`; immutable)

## Purpose
A technology-neutral guide to designing independent, integrated modules that share reference data (domain: Organisasi & Sumber Daya Manusia). Readers: architects and developers. Modules A, B, C, D are illustrative.

## Page types and directories
- `source` in `sources/`: one summary per raw file.
- `guide` in `guide/`: hub page per guide section; lists its child pages in reading order.
- `concept` in `concepts/`: principles, glossary, shared ideas.
- `module-type` in `modules/`: module classification, scope criteria, module edge cases.
- `table-type` in `tables/`: table classification and accountability.
- `pattern` in `patterns/`: communication flow, payload, technology requirements, integrity rules.
- `usecase` in `usecases/`: what happens to each module and table type.
- `decision` in `decisions/`: open choices with options and conditions.
- `ops` in `ops/`: governance, monitoring, checklists, source reliability.

## Frontmatter
Required: `type`, `title`, `tags`, `sources`, `created`, `updated`. Source pages also: `authors`, `url`, `raw`, `ingested`.

## Tags
- `proposal`: reasoned recommendation, not from a verified source.
- `unverified`: depends on source material marked unverified.
- `partly-verified`: backed by cited primary documentation in the research report.
- `edge-case`, `option`, `example`.

## Conventions
- Links use standard Markdown syntax with relative `.md` paths.
- Technology-neutral: name capabilities (event broker, schema registry), not products, except as labelled examples.
- Claims from unverified source sections carry an explicit hedge.
- Each page is about one thing, under 400 lines.
- Hub pages in `guide/` define reading order; `System design guide.md` (one level above `wiki/`) is generated by concatenating them in that order via `build_guide.py`.

## Index
Flat `index.md` until the wiki passes ~150 pages.
